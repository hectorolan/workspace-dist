# cli/ — the `ws` client, its modules, and the forged tools

`ws` (`node cli/ws.js`) is **THE client** for everything: the audit trail, documents,
conversations, plans, email, the inbox, the schedule, and git. One implementation, one
runtime, on every host — every script reuses it (or the `util/` modules underneath) and
never reimplements an API, git, or email call.

This README is the authoritative home for three enumerables: the **subcommand roster**,
the **shared modules**, and the **forged-tool inventory**. Other docs cross-reference it
and never restate them. What the API itself does — endpoints, schema, auth, the
page-comment lifecycle — lives in `server/README.md`.

## Layout

| Path | What lives here |
|---|---|
| `ws.js` | The CLI entry point — argument parsing + dispatch; the logic lives in `util/` |
| `util/` | The shared implementation modules: API, git, email, schedule, time. Imported by `ws.js`, the runners, and every forged tool |
| `util-tools/` | Forged token-saving scripts (tools over turns) — the inventory is below |
| `test/` | `node:test` suites for both (`node --test cli/test/*.test.js`) |
| `package.json` | npm-workspace member; deps install once at the repo root |

## Client subcommands (`ws`)

The complete `node cli/ws.js <cmd>` surface — this table is authoritative (CLAUDE.md's
logging convention points here; never restate a partial roster elsewhere). Exit code is
`0` on success unless noted.

| Category | Command | Tokens | What it does |
|---|---|---|---|
| Audit trail | `log [-r <repo>] [-a <agent>] <area> <status> <message>` | zero | Append one audit line (`POST /log`). Offline it appends to `<WS_DATA_DIR>/fallback/log.md`; `ws pull` replays it when the API is healthy. |
| Audit trail | `query [--summary \| --messages \| --message-id <id>] [--repo <r>] [--area <a>] [--status <s>] [--kind <k>] [--state <s>] [--q <text>] [--days <n>] [--limit <n>] [--json] [--include-retired]` | zero | The whole read surface — reading never needs `msg`, which only writes. `--summary` = per-repo status sweep · `--messages` = message index (bodies elided; `--kind`/`--q` filter, `--state` filters page comments by lifecycle state) · `--message-id <id>` = one message's full body (the id comes from `--messages`) · default = compact log lines. `--include-retired` un-hides retired repos in the sweep. |
| Documents & conversations | `msg <kind> <subject> <ref> <body-file> [meta-json]` | zero | **Write only** — store a full document (`POST /message`); `ref` dedupes on `(kind, ref)`. To read a stored document use `query --message-id <id>`. |
| Documents & conversations | `email-out <subject> <body-file> [meta-json]` | zero | Capture an already-sent email into the DB (senders call this automatically). |
| Documents & conversations | `conv-title <id> <title>` | zero | Set a conversation's title. |
| Documents & conversations | `conv-status <id> <active\|archived>` | zero | Archive/unarchive a conversation. |
| Documents & conversations | `thread get <doc-kind> <doc-ref> [--json]` · `thread list [--doc-kind <k>] [--limit <n>] [--json]` | zero | Document threads (`server/README.md` "Document threads"): `get` = one document's thread — entries with roles and full bodies, flat order; `list` = anchors with entry counts, newest activity first (`--doc-kind conversation` = the document-less threads). Read-only; entries are posted by the server at comment intake, by the inbox runner (reply), or via `threadPost` in `util/apiclient.js` — a session that generates a new document from a conversation attaches the origin with `threadPost({docKind, docRef, messageId, role: 'trigger'})` (rendered at the top of the doc's thread). Re-anchoring (`threadMove(id, {docKind, docRef})` → `PATCH /thread/:id`) is the only mutation — no delete; the monthly backlog prune uses it to carry prior-month backlog entries into their month's history plan. Bodies are captured page content — untrusted quoted data (WS-H2). |
| Plans | `plan list [--kind <k>] [--status <s>]` | zero | The plan index. |
| Plans | `plan get <slug>` | zero | One plan's full body, under the `# slug \| kind \| status \| date \| title` banner the API renders for human reading. Editing that output and writing it straight back (`plan get x > f` … `plan set x --file f`) is safe: the API strips its own banner on write, so the round trip is byte-identical (contract: `server/README.md` "Plan header"). |
| Plans | `plan history <slug> [--limit <n>]` | zero | Revision snapshots, newest first. |
| Plans | `plan set <slug> [--title "<t>"] [--file <path> \| --body "<md>"] [--kind <k>] [--status <s>] [--repo <r>] [-a <agent>]` | zero | Upsert (the DB is the source of truth; kinds listed in `server/README.md`). **Create requires `--title` + a body; update = any subset** — e.g. the archive one-liner `plan set <slug> --status archived` (archived is a STATUS; the plan keeps its kind), or a title-only rename in place (preserves body + created-date, bumps updated-date, snapshots a revision). **No offline fallback**: if the API is down this fails loudly and the agent logs `blocked`. |
| Stations | `station list [--stale-minutes <n>] [--json]` · `station get <env> [--json]` · `station report` | zero | The station registry (SYSTEM.md "Station registry"): `list` = the roster with control-plane-side findings (`STALE` after 45 min ≈ 3 missed ticks, `NEVER REPORTED` for a configured station with no row); `get` = one station's full stored report; `report` = collect this station's `env-doctor` payload + public IP and PUT it now (what the pull tick does automatically — exit `1` if it could not land). |
| Email & inbox *(runners; scheduled — see SYSTEM.md)* | `email --subject <s> --body-path <file> [--to <addr>] [--in-reply-to <id>] [--html]` | zero | Send an email via SMTP — the send primitive (`email-out` records a send). Exit `2` = no password/identity, `3` = empty body. |
| Email & inbox | `inbox-check` | zero | Peek the IMAP inbox, print new-message file paths; read-only, no dispatch. |
| Email & inbox | `run-inbox` | **AI** | The inbox poll: email + `page-comment` intake (waiting-state only) → `/claim` → dispatch orchestrator → reply posted as a role-`agent` thread entry on the comment's anchor (`server/README.md` "Document threads") → email reply → `/seen` (+ reply id). |
| Scheduling *(one live job host only — ownership-guarded)* | `scheduler` | indirect | The long-running loop; arms every non-disabled `configs/jobs/jobs.json` job. Resolves only on signal exit; exit `1` = ownership/config refusal. |
| Scheduling | `run-job <job> [--if-missing]` | **AI** | Run one scheduled job by name on demand. |
| Sync & maintenance | `pull` | zero | Freshness net: pull-if-behind + `ensure-deps` + PR watch + test-plan close sweep (active plans judged against the stored baseline — SYSTEM.md "Test-plan close on a green run") + stale-status sweep + fallback replay + self-restart check + log-API tunnel ensure + station report (quiet no-op offline). |
| Sync & maintenance | `sync <commit message> [--paths <p1> <p2> ...] [--no-guard]` | zero | The one workspace git call: pull → stage → commit → **ci-guard** → push. With `--paths` only those pathspecs are staged and anything else left dirty is reported, so concurrent sessions can't sweep each other's work. The ci-guard is this main-direct repo's only pre-push gate (SYSTEM.md "ci-guard"): it runs the CI subset the staged paths can affect and refuses a push that would land main red. Exit `2` = missing message, `1` = guard refusal (changes stay staged). |
| Sync & maintenance | `ensure-deps` | zero | Install deps if `node_modules` is missing/stale (freshness net; `pull` runs it each tick). |
| Sync & maintenance | `backup` | zero | Daily SQL-text dump → `workspace-backups` repo, then re-runs the rolling prune. |
| Sync & maintenance | `health` | zero | Ping the API (`GET /health` → `{ok, db, entries}`). |

**Tokens.** Only two commands spend AI tokens: `run-inbox` (one orchestrator session per
request, plus one cheap haiku call to title a new conversation) and `run-job` (the compose
session for agent jobs). `scheduler` is *indirect* — the loop itself is deterministic; it
only fires those two. Everything else is plain HTTP / git / SMTP / IMAP, which is why
`ws pull` can run every 15 minutes on every host for free, why the PR watch and fallback
replay are zero-token, and why reading or writing the audit trail, plans, and reports costs
nothing. The single seam is `util/agent.js` — **a command that does not reach it cannot
spend a token**, so that import is the one thing to check when auditing a new subcommand.

```bash
node cli/ws.js log -a newsroom digest done "archived daily-digest (DB message)"
node cli/ws.js query --summary --days 14          # portfolio status sweep
node cli/ws.js plan get backlog                   # the pending-work queue
node cli/ws.js sync "chore: update SYSTEM.md"     # workspace push, one call
```

## Shared modules (`cli/util/`)

The implementation behind the commands above. Anything mechanical belongs here, once —
a script that reimplements an API/git/email call instead of importing these is a
compliance violation, not a shortcut.

| Module | Role |
|---|---|
| `index.js` | Barrel re-export — the import surface for forged tools (`../util/index.js`): git (`syncWorkspace`, `commitAndPush`, `pullIfBehind`), the API client's full verb set, `clock`, `sendEmail`, `runAgent`, `pruneRepo`, `sweepPRs` |
| `apiclient.js` | **THE** HTTP client for the central log API, behind every `ws log` / `query` / `plan` / `msg` on every host. **Zero npm dependencies** (global `fetch` + `node:fs`), so it works on a fresh clone before any install — and owns the offline fallback + replay, plus the **one retry on a died-mid-request connection** and only for repeatable methods (`GET`/`PUT`/…; an appending `POST` falls back instead of risking a duplicate row — `cli/test/apiclient-socket.test.js`) |
| `audit.js` | **The never-silent audit write** (backlog 42) — the wrapper every scripted writer uses when the state change has ALREADY happened and will never be retried (a closed test-plan, a refused push). Calls `log()`, never throws back at a caller that already acted, and on failure prints a loud `AUDIT WRITE FAILED` diagnostic AND appends the line to `<data>/fallback/audit-failures.md`. No retry queue: `apiclient` already queues offline lines for `ws pull` to replay, so the bar here is "never silent", not "never fails" |
| `clock.js` | **The one time source** — calendar dates, hour-of-day, log stamps, always in the schedule timezone (`configs/jobs/jobs.json`), never raw UTC. Born from the 2026-07-20 digest incident, where mixing UTC dates with host-local hours composed "tomorrow's" digest a day early |
| `ciguard.js` | The pre-push CI gate for `ws sync` (backlog 58) — selects the affected gates from the staged paths (typecheck / server tests / cli tests, fast-first, fail-fast), decides refuse vs warn, and hands the caller one loud audit line. Everything that is not a gate exiting non-zero with recognisable diagnostics degrades to "push allowed", so a broken toolchain can never lock a station out of syncing |
| `ansi.js` | **Colour is display, never data** — `stripAnsi` for everything that PARSES subprocess output, `plainOutputEnv` for everything that SPAWNS it. Both layers exist because a station shell exporting `FORCE_COLOR=3` made a red `node --test` run arrive wrapped in escape sequences, which the ci-guard's anchored parsers read as "no recognisable diagnostics" — the gate silently skipped and the baseline tally went blind (windows-pc, 2026-08-18) |
| `probe.js` | **The one way to spawn an external tool and capture its output** (`gh`, `az`, `claude`, …) without the DEP0190 `shell:true`+argv deprecation: POSIX spawns a real argv vector with no shell; Windows builds ONE explicitly-quoted cmd line (`.cmd` shims require a shell there). Used by `nsgcheck.js`, `env-doctor.js` and `station-bootstrap.js`; own suite `cli/test/probe.test.js` |
| `encoding.js` | The script-encoding rules, shared by the ci-guard's `encoding` gate and CI (SYSTEM.md "Encoding guard") — shell scripts must be BOM-free (a BOM made bash echo a line containing a token on 2026-07-28), `.ps1/.psm1/.psd1` must be pure ASCII (PowerShell 5.1 reads a BOM-less file as ANSI). Opposite directions, so strictly file-type scoped; a byte scan, never a parse; findings carry offset and line **number** only, never the offending line |
| `gitsync.js` | **The one git client** — pull/stage/commit/push shared by `ws sync` and the forged tools, including `--paths` scoping, the sweep warning, and the `preflight` seam the ci-guard hangs on (stays pure git itself) |
| `smtp.js` | **The one email sender** (`ws email`) — Gmail SMTP, sends from the agent `+alias` with `Reply-To` back to it, sets `X-Workspace-Agent` so the inbox poller never mistakes agent mail for a request, and captures every send as `email-out` automatically |
| `agent.js` | **The provider seam — and the only module that spends AI tokens.** The only place that knows which AI CLI is installed: swap providers with `AGENT_PROVIDER`, and nothing else in the system changes. Runs on the cheapest model by default (`AGENT_MODEL`, default haiku) because the dispatcher session only delegates to a subagent, whose own `model:` does the real work. Also the seam that makes the runners testable without a real agent CLI |
| `repos.js` | Filters retired repos out of the portfolio sweep **at read time** (config: `configs/repos.json`) — the log stays complete and honest; the filtering lives in the one client, not in the data |
| `inbox.js` | IMAP capture of the CEO's email requests + the hub page-comment poll, including `fencePageContext` (the WS-H2 trust boundary — see `server/README.md`) |
| `runinbox.js` | The orchestrator's mailbox loop: capture → `/claim` → one agent session per request → threaded email reply → `/seen` |
| `runjob.js` | Scheduled job runner: run logging, network wait, compose via the provider seam, skip-if-exists, compliance audit, delivery, audit line. **One attempt** — retries are the scheduler's job (`retries`/`retryDelayMin` in jobs.json) |
| `scheduler.js` | The container's clock — reads `jobs.json` as data, arms one cron per non-disabled job in the configured timezone, refuses to overlap a job with its own previous run, plays the `@reboot` role via boot catch-up, and polls the self-restart marker |
| `selfrestart.js` | Self-restart on relevant pulls: diff the pulled range → syntax-gate the changed entry files → touch a restart marker. A broken push keeps the old code running and logs one loud `failed` line instead of boot-looping |
| `prwatch.js` | PR watch — the deterministic PR-state logger run by `ws pull` (zero tokens). Also closes test-plans on merge, holds plans with unperformed manual cases, and reconciles PRs merged between ticks. One of the scripted log-writer exceptions |
| `statussweep.js` | Stale-status sweep — run by `ws pull` right after the PR watch (zero tokens): resolves a `(repo, area)` whose newest log line is `PR-open`/`blocked` but whose work is PROVABLY finished (every cited PR merged/closed on GitHub; every cited test-plan done/archived in the DB) with one `done` line; `deployed-staging` and anything with missing/ambiguous evidence is always left. Idempotent by construction — the resolution line is terminal, so the area is never selected again. One of the scripted log-writer exceptions (SYSTEM.md "Stale-status sweep") |
| `ceo.js` | **Who the system works for**, as config — `ceo` in `configs/environments.json`, read here and nowhere else. Feeds the CEO block's lead line, the `## Needs <CEO>` heading matcher, the "is this case waiting on a human" test, and the orchestrator prompts, so no source file hardcodes a name (CLAUDE.md's invariant: a fresh clone must already be a working system for ITS operator). Deliberately NOT the CEO's email — `OWNER_EMAIL`/`AGENT_EMAIL` own that in env and the mail path reads them directly. Fail-soft: an unset name degrades to the label "the CEO", never to a guess (unlike mail identity, which refuses to send) |
| `planclose.js` | Evidence-based test-plan closure for **main-direct repos** (which have no PR merge for `prwatch` to hook, so their plans used to accumulate forever) plus the **CEO block**. Runs inside `ws sync` on the same green tallies that advance the baseline: a plan closes when every automated case ID it declares is in the baseline's covered set (the last green run of each suite, not this run alone); one still holding unperformed manual cases stays active and gets a blockquote pinned at its top naming only what the CEO must do. Coverage is judged before the human hold, so unfinished work is never blamed on the CEO. One of the scripted log-writer exceptions |
| `baseline.js` | The regression baseline — per repo and per suite, the last green run (commit, pass count, the `TP-<slug>-NNN` case IDs it covered), carried as a central-DB plan `test-baseline-<repo>` of kind `baseline`, never a file. Extracts case IDs out of test output, compares a run against the record (`absent`/`matched`/`regressed`/`stale`, `absent` being normal) and advances it on green. Read by `ws sync` via ci-guard, and the coverage source `planclose.js` closes against (behaviour: SYSTEM.md "Regression baseline") |
| `planreap.js` | The plan-scoped temp-test reaper run pre-commit by every guarded `ws sync`: deletes `@throwaway` tests and untags `@promote` tests whose test-plan has closed, and strips the removed case IDs out of the DB baseline so the cleanup can never read as a regression. Stateless and idempotent (the plan status IS the state) and conservative by construction — any doubt leaves the file byte-identical with a note, so it can never fail a push (SYSTEM.md "Plan-scoped temp-tests") |
| `backlogprune.js` | The monthly backlog prune (SYSTEM.md "Monthly backlog prune"): archives whole `## Resolved (date)` sections and marker-dated items from a month earlier than the current one into `backlog-history-YYYY-MM` DB plans (kind plan, status archived), bucketed by the item's own date. History is written and read-back verified BEFORE the backlog is trimmed; anything ambiguous stays with a reason — losing a pending item is catastrophic, keeping a stale one merely untidy. Idempotent, append-only merge |
| `skillsync.js` | Upstream check for vendored skills (`.claude/skills/sources.json`): on a sha change it refreshes a throwaway clone, verifies it with `agent-doctor`, opens a review PR and **never merges**. No environment gate — the scheduled gh-workflow triggers it in the control plane, so no station is special; the local stamp (and `--force`) only throttle manual station runs |
| `station.js` | The station-registry reporter (`ws pull` tick + `ws station report`): PUTs this station's observed state — the `env-doctor` `payload()` **consumed as-is, never re-derived**, plus public IP (fail-soft probe) — to `PUT /station/:env`. Probes API health FIRST so an offline tick skips collection entirely; no outcome can throw, change the tick's exit code, or write a log line |
| `tunnel.js` | The SSH tunnel to the central log API — the encrypted transport for environments that aren't the API's host (PC → VM). Ensured every `ws pull` tick, so it self-heals after a reboot or a dropped link |
| `nsgcheck.js` | Does the control plane's NSG ssh rule still admit THIS station's public IP? Compares the measured IP (`station.js`'s `publicIp()`, reused) against the Allow-inbound port-22 rules read with `az network nsg rule list`, and on a mismatch FAILs with the exact `az network nsg rule update ... --source-address-prefixes <new-ip>` for the CEO to run — names from `configs/environments.json` `controlPlane.azure`, never code. **Read-only**; absent/unauthenticated `az`, no tunnel, no public IP = INFO/skip. Cached per station so the 15-min tick pays only the IP probe (SYSTEM.md "NSG ssh allowlist"). Used by env-doctor (`nsg-ssh-allowlist`), by the tunnel supervisor on a connect failure, and by `station-bootstrap` for its prefix maths |
| `controlplane.js` | env-doctor's control-plane check group: the VM **host** facts git cannot see (the `deploy.sh hub` crontab line, the prod compose file + deploy clone deploy.sh wires, and per-service env health — every service under `~/agent` judged against ITS OWN repo's `.env.example`, three states per capability; behaviour spec + marker grammar: SYSTEM.md "Per-service env health"), probed **read-only** over the station's existing `logApiTunnel.sshTarget` at most once/day (cache+stamp in `<WS_DATA_DIR>/control-plane/`; `env-doctor --control-plane` forces). No secret VALUE ever rides the wire — counts, present/absent, service dir names and var NAMES only; unreachable SSH is INFO/skip, never FAIL |
| `features.js` | Loader/validator for the **declared feature registry** (`configs/features.json` — design `ws plan get features-ui-restructure-design`) plus the pure cell-state derivation `GET /feature` builds on (`checkState`/`combineStates`/`jobCellState`, `parseScope`/`scopeIncludes`). Refuses unknown scope forms, envs/kinds not in `configs/environments.json`, `job:` names not in `jobs.json`, duplicate ids, malformed evidence, absent/empty `description` (C-2 — every feature carries colloquial operator-facing prose); `cli/test/features.test.js` keeps the shipped registry valid against the real configs. Never throws — errors surface as a list (the endpoint answers 500; response contract: `server/README.md` "Feature registry") |
| `deps.js` | Dependency self-heal — compares the lockfile against the installed tree and installs when a pull moved it under a running system (an imapflow bump once broke a live inbox tick this way). Zero-dependency by design: it's what installs them |
| `backup.js` | Daily DR dump of `logs.db` as plain SQL text into the `workspace-backups` repo, pushed — git history is the retention |
| `prune.js` | Rolling 30-day rotation of the per-machine data dir (`WS_DATA_DIR`). The DB holds the full history; the data dir holds only transient runtime state, so anything older is deleted outright |
| `distmanifest.js` | The distribution export manifest (`configs/distribution.json`) — loader, shape validator, rule compiler and include-set resolver, plus the name/secret line scanners. ONE rule set shared by the manifest tests (`cli/test/distmanifest.test.js`) now and the Phase 3 exporter later, so the reviewed manifest and the shipped tree can never disagree (structure: `docs/distribution.md`; plan `ws plan get nexus-distribution-packaging`) |

## Forged tools (`cli/util-tools/`)

The ONE dedicated home for every token-saving utility script (Hector, 2026-07-19). When
the orchestrator or devops is about to do mechanical, repeatable, or parameterizable
work with agent turns, it first checks this inventory; if a tool exists it runs it (zero
reasoning tokens), and if the work will plausibly recur it forges a new tool here
instead. **Tools over turns**: mechanical work runs through deterministic scripts, never
through the LLM twice.

Rules (from `ws plan get nodejs-runtime-restructure`):

- Node.js only, importing the shared modules **relatively** (`../util/index.js`) for
  git/api/email mechanics — never reimplement those calls. Relative imports mean forged
  tools run with zero npm install, same as `ws.js` itself.
- Secrets from env only; a tool never carries credentials or prompts to other AIs.
- Every tool lands via the normal `ws sync` push — no PR, no gate — but ONLY in this
  directory, with its inventory row added in the same commit.
- Scripts created anywhere else are a compliance violation (flagged loudly, never
  silently moved).
- Add a test under `cli/test/` when a tool has logic worth testing.

| Tool | What it automates | Tokens it replaces |
|---|---|---|
| `env-doctor.js` | One-call proof that this station is **wired AND able to work**. Connectivity: node version, WS_ENV identity + schedule ownership, deps freshness, **ci-guard gates armed** (a station whose gates cannot run pushes unverified — safe by design, invisible until asked), git sync state, log API reachability. Capability (kind-aware from `configs/environments.json`, so a container is never failed for Docker Desktop or a Windows task): `~/.claude/settings.json` vs the desired state in `configs/harness-settings.json`, `activeProjectRepos` cloned as siblings under `sources/`, tool presence + reported versions (node/git/gh/claude/ssh/docker/az), **git on the MACHINE PATH** (an S4U task cannot see user PATH), `Claude-WorkspacePull` registration, and the `gh` OAuth scope set (informational). **NSG ssh allowlist vs this station's public IP** (`util/nsgcheck.js` — the only FAIL is a measured mismatch, and it prints the exact `az` fix command). Control plane (kind-aware — only a station with `logApiTunnel.sshTarget` probes; see `util/controlplane.js`): the VM host's deploy crontab line, prod compose wiring, and per-service env health (each `~/agent` service vs its own repo's `.env.example`, SYSTEM.md "Per-service env health"), read-only over SSH, daily-cached; `--control-plane` forces a fresh probe. **Feature-registry drift** (`feature-registry`): the declared catalog `configs/features.json` vs reality — unregistered jobs/tools and dead `check:` evidence WARN, a broken registry FAILs (rules: SYSTEM.md "Feature-registry drift check"). | `station-bootstrap.js` | The whole "add a station" procedure as one resumable, idempotent walk: the ten ordered steps of `.claude/SETUP.md` "New environment bootstrap", in **dependency order** (the `configs/environments.json` entry first — and checked on `origin/main`, since everything else resolves from it), each ending in a machine check, with `env-doctor` folded in as the verifier for six of them. **Probes and instructs only** — it verifies a variable is SET and, where a real probe exists, that it WORKS, prints the exact command for a HUMAN, and never reads/echoes/writes a secret value (plan D5; `redactSecrets` scrubs every line out as a backstop). Measures rather than assumes: NSG coverage (a successful ssh connection proves it; the rule is read only on failure or `--deep`) and `ssh-keyscan`. Acceptance step includes a **project-work smoke check**. Windows: `setup-scripts\windows\station-bootstrap.cmd`. Transcript at `<WS_DATA_DIR>/setup/station-bootstrap.log` | The multi-hour, seven-incident manual station install of 2026-07-28 — and the re-audit every later station or repair would repeat by hand |
| `encoding-check.js` | Whole-tree run of the script-encoding guard (`--staged` / explicit paths / `--json`): BOM in a shell script, non-ASCII in a `.ps1`. What CI runs as its first step, and the one-call answer to "is any script in this repo mis-encoded" — reports file/offset/line, never the line text, and never rewrites a file | The per-file manual PowerShell parser+byte check in `setup-scripts/windows/README.md`, repeated once per script |
| `test-baseline.js` | The regression baseline read/update flow: `show` (read-only state per suite), `check` (run + compare, exit 1 only on a proven regression), `record` (run + write the GREEN suites back). Carrier is a central-DB plan — slug `test-baseline-<repo>`, kind `baseline`, NEVER an `ops/test-baseline.json` file. Four states, `absent` being a normal one. `ws sync` does this automatically for the workspace repo via ci-guard; this tool is the on-demand and cross-repo path | The "was it always like that?" investigation after every red suite — reconstructing the last green commit and its pass count by hand from `gh run list` and git log |

## Conventions

| Rule | Why |
|---|---|
| `ws` is the one client | One implementation of every API call, on every host. New scripts import `util/`; they never hand-roll `fetch`, `git`, or SMTP |
| Zero npm dependencies on the core path | `apiclient.js` and `deps.js` use only global `fetch` + `node:*`, so logging and dependency self-heal work on a fresh clone before any install |
| All dates from `clock.js` | Never `new Date().toISOString()` for a calendar date — the schedule timezone is the one clock (raw instants like `Date.now()` are fine) |
| Tools over turns, rule of two | About to do the same mechanical thing a second time by hand → forge a tool in `util-tools/` and add its inventory row in the same commit |
| Tests live in `cli/test/` | `node --test cli/test/*.test.js`; CI runs the same suites |
